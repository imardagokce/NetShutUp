# Selftest (Tester Mode) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Self-test (for testers)" menu item and `selftest` command that runs every profile through a real apply → verify → revert cycle, collects an allow-listed set of diagnostic facts, and writes a masked `.md` + `.json` report locally.

**Architecture:** New `selftest` module. Pure parts (data model, masking, markdown rendering, snapshot comparison, the runner against an `Env` trait) are tested with fakes; thin Windows-facing parts (diagnostic collectors, file writing, menu wiring) sit on top. The runner reuses the existing engine (`apply::plan/apply/revert`, `dns::run`) so it tests the real code. Shared plan helpers move out of `commands.rs` into `settings/plan.rs` first.

**Tech Stack:** Rust 2024, existing `windows`, `serde`, `serde_json`; add `GlobalMemoryStatusEx` (feature already present), `Win32_Globalization` for the locale name.

**Spec:** `docs/design/2026-11-17-selftest.md`

## Global Constraints

- Nothing is written to the system before the consent screen (default No) and, for a real run, an administrator copy. No network upload of any kind: the report is only written to local files.
- Report files: `NetShutUp-selftest-<YYYYMMDD-HHMMSS>.md` and `.json`, written to `%ProgramData%\NetShutUp\reports\` and copied to the current user's Desktop when it can be found; the folder is opened and the path printed.
- JSON `schema` is `1`. Statuses: `pass`, `fail`, `skip`, `info`; icons in markdown: ✅ ❌ ⏭ ℹ️.
- Masking (verbatim): only the provider addresses in `settings/provider.rs` stay readable; other private IPv4 → `a.b.x.x`; every other IPv4 → `x.x.x.x`; every IPv6 → `x:x::x`; MAC → first three bytes kept, e.g. `5C-FB-3A-xx-xx-xx`; adapter GUID → first 8 characters. Every free-text `detail` passes through `mask::scrub` before it enters the report.
- Diagnostics are limited to the allow-list in the spec (table "Toplanan tanılama bilgisi") and are never collected outside the `Diagnostics` struct. Never collected: user name, computer name, SSID, full MAC/IP, serial numbers, installed software (network drivers excepted), file paths, proxy address.
- A cycle: snapshot of **all** catalog values → `apply::apply` (auto-confirmed, one backup) → `dns::run` when the profile has DNS targets → internet check → `apply::revert` → snapshot equals the first one → internet check → backup marked reverted. A failed step skips the rest of that profile, reverts, continues with the next profile. A failed revert stops the run and sets `all_restored: false`.
- A DNS trial that falls back because the network blocks DoH is `info`, not `fail`.
- Program text is English; commits conventional, no Co-authored-by line. Run commands from `modern/`; full suite `cargo test`.

## Review Focus

1. Revert fails after apply: the run stops, `all_restored` is false, the report starts with a red "NOT everything was restored" box and the manual command `netshutup-modern revert`. → Task 5 `failed_revert_stops_and_marks_nothing_restored`, Task 1 `render_puts_the_not_restored_warning_first`.
2. Raw addresses leak through error text (e.g. a `Debug` string with `192.168.1.5`). → Task 1 `scrub_masks_addresses_inside_free_text`, `report_never_contains_unmasked_addresses`.
3. The tester closes the window mid-cycle: the system stays applied. A marker file is written at the start and removed at the end; the menu header warns when it exists. → Task 5 `marker_is_set_during_the_run_and_removed_after`, Task 6 `header_warns_about_an_unfinished_selftest`.
4. The report cannot be written (disk full, no rights): the markdown is printed to the screen instead and the exit code is non-zero. → Task 6 `unwritable_report_dir_is_an_error_the_caller_can_handle`.
5. No usable Ethernet/Wi-Fi adapter: environment check fails, cycles are skipped, nothing is written. → Task 5 `no_adapters_skips_the_cycles_without_writing`.
6. A blocked DoH network must not make the self-test look like a program bug. → Task 5 `dns_fallback_is_info_not_fail`.

### Task 5: The runner

**Files:**
- Create: `modern/src/selftest/runner.rs`
- Modify: `modern/src/selftest/mod.rs` (`pub mod runner;`), `modern/src/settings/store.rs` (`FakeStore.fail_after_writes: Option<u32>`: every write once `writes >= n` fails)

**Interfaces:**
- Consumes: Tasks 1–4, `apply`, `backup`, `dns`.
- Produces:

```rust
pub struct EnvAdapter { pub guid: String, pub name: String }
pub trait Env {
    fn store(&self) -> &dyn Store;
    fn resolver(&self) -> &dyn Resolver;
    fn adapters(&self) -> Vec<EnvAdapter>;      // the Ethernet/Wi-Fi hardware adapters
    fn windows_build(&self) -> u32;
    fn elevated(&self) -> bool;
    fn backup_dir(&self) -> std::path::PathBuf;
    fn timestamp(&self) -> String;               // YYYYMMDD-HHMMSS
    fn set_in_progress(&self, on: bool);         // marker file
}
pub struct Snapshot(Vec<(String /*id*/, Option<String> /*adapter*/, State)>);
pub fn snapshot(store: &dyn Store, adapters: &[EnvAdapter]) -> Snapshot;     // EVERY catalog setting
pub fn differences(before: &Snapshot, after: &Snapshot) -> Vec<String>;       // uses reader::matches; text via reader::format and mask_guid
pub fn run(env: &dyn Env, profiles: &[Profile], diagnostics: Diagnostics, say: &mut dyn FnMut(&str)) -> Report;
```

`run`: `set_in_progress(true)` first and `false` last (also on every early return); Phase A checks (elevated, adapters ≥ 1, backup dir writable, internet via `dns::internet_works`, Windows build); Phase B (one check per catalog setting: readable on every adapter/system; per profile: plan builds and `apply::check` is `Ok`; snapshot before == after building previews); Phase C cycles per the Global Constraints (DNS read-back check: for each adapter whose DNS was changed and kept, `dns.resolver` reads back as the chosen provider's `state()`); Phase D (start-vs-end snapshot, `all_restored`). With zero adapters: Phase C is skipped (`skip` checks) and nothing is written. `say` receives one progress line per step.
