# Firewall strict tier (6b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** Privacy offers four optional firewall items, each asked separately, backed by the normal engine.

**Spec:** `docs/design/2026-11-18-firewall-6b.md` (read it first). Builds on 6a (`settings/firewall.rs`, `Source::Firewall`).

## Global Constraints

- Rust 2024, `windows` 0.62.x. From `modern/`: `cargo test` and `cargo build --release` green, **no warnings**.
- Never run `apply`, `revert`, `selftest` or change firewall state; real COM write paths are only compiled. Only a read-only real test may run.
- Tests first. Files are CRLF (Edit tool or Python with `newline=""`). One commit per task, conventional prefix, **no Co-authored-by line**, do not push.
- Never parse `netsh` text. Program text is English.
- Setting ids (never change): `firewall.rule.block_telemetry`, `firewall.public.network_discovery`, `firewall.public.file_printer_sharing`, `firewall.public.remote_assistance`; scope `System`; labels `[(0,"off"),(1,"on")]` (names: `Telemetry service outbound block`, `Network discovery rules (Public)`, `File and printer sharing rules (Public)`, `Remote assistance rules (Public)`); defaults `Dword(0)` for the rule, **`Dword(0)`** for the three groups (Windows disables them on Public).
- Rule (verbatim): name `NetShutUp: block telemetry service`, grouping `NetShutUp`, service `DiagTrack`, direction out (2), action block (0), enabled, profiles all (`0x7FFFFFFF`). Group names: `@FirewallAPI.dll,-32752`, `@FirewallAPI.dll,-28502`, `@FirewallAPI.dll,-33002`; Public profile mask `4`.
- Question texts (verbatim, default No): telemetry: `Block the Windows telemetry service from connecting out (adds a firewall rule that is removed again on revert)?`; discovery: `Turn off network discovery rules on Public networks? Other devices will no longer find this computer on public Wi-Fi.`; sharing: `Turn off file and printer sharing rules on Public networks? Sharing and printers will not work on public networks.`; assistance: `Turn off Remote Assistance rules on Public networks?`.

## Task 1: Catalog, COM and profile `optional`

**Files:** `settings/firewall.rs`, `settings/catalog.rs`, `settings/store.rs`, `settings/profile.rs`, `modern/profiles/privacy.json`.

**Produces:**
- `firewall::Field` gains `Rule` and `Group(GroupId)` (or equivalent), with `firewall::read/write` handling them: rule → `Rules.Item(name)` exists / `Rules.Add(rule)` built through `CoCreateInstance(NetFwRule)` with the properties above / `Rules.Remove(name)`; groups → `IsRuleGroupEnabled(4, group)` / `EnableRuleGroup(4, group, bool)`. Write 1 when already 1 (or 0 when absent) is a no-op success.
- `Profile.optional: Vec<OptionalAssignment { id: String, set: Desired, question: String }>` (`#[serde(default)]`, `deny_unknown_fields`), validated like `settings` plus: not also listed in `settings`; `privacy.json` gets the four items with the verbatim questions and `{ "dword": 1 }` for the rule and `{ "dword": 0 }` for the three groups.
- `Profile::optional_targets(&self) -> Vec<(OptionalItem, Target)>` where `OptionalItem { id: String, question: String }` (system-scope targets; no adapter expansion).

## Task 2: The question flow, self-test, docs

**Files:** `commands.rs`, `settings/plan.rs`, `selftest/runner.rs`, `selftest/system_env.rs` (only if needed), `modern/README.md`, root `README.md`, `docs/design/2026-11-16-alpha-release.md` (stage 6 line), `2026-11-18-firewall-6b.md` (status), `docs/TESTING.md`/`TESTING.tr.md` (one sentence: the Privacy step may ask optional firewall questions in normal use; the self-test answers yes and undoes them).

**Produces:**
- `plan::optional_changes(store, profile, adapters_unused, third_party: Option<&str>) -> Vec<OptionalChange { item: OptionalItem, change: PlannedChange }>`: only items that would change something (`is_needed()`), none when a third-party firewall is registered.
- `commands`: preview lists them under `Optional (you will be asked):`; `write_profile` (CLI and menu) asks each question through the same `ask` closure used for the confirmation, **after** the main confirmation and **before** the apply, and appends the approved ones to the plan so they share the single backup; "No"/non-interactive → skipped; `--dry-run`/`preview` print `would ask: <question>`; the final summary counts them.
- Self-test runner: for a profile with optional items it adds all of them (as if approved) to that cycle's plan; add an Info check `optional.firewall` listing what was exercised; consent screen text gains one sentence (the optional firewall items are tried and undone).
