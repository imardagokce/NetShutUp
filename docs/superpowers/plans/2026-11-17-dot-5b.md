# Experimental DoT (5b) and Selftest Safety Net Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** (1) The self-test first exports the relevant registry keys and creates a system restore point, and records both in the report. (2) The DNS trial chain tries DoT after DoH per provider, with a backup/restore of Windows' global encrypted-DNS server entries; everything experimental is verified by read-back and reported.

**Architecture:** Safety net = two new `Env` methods used by a "safety" phase in the runner. DoT = a `DotBackend` trait (real one uses the registry and `netsh`), a `.dot.json` sidecar next to the apply backup, `dns::run` over (provider, method) pairs, and restore-on-revert.

**Spec:** `docs/design/2026-11-17-dot-5b.md` (read it first). Parents: `2026-11-17-dns-doh-5a.md`, `2026-11-17-selftest.md`.

## Global Constraints

- Rust 2024, `windows` 0.62.2 (add feature `Win32_System_Restore` when needed). Run commands from `modern/`; full suite `cargo test` must stay green with no warnings (`cargo build --release` too).
- **Never run** the program's `apply`, `revert` or `selftest`, `netsh dns add/delete`, `reg export` against the real machine, or any real restore-point call, in tests. Real-system code is only exercised by compiling it. Read-only checks (reading registry) are fine.
- Tests first (see failing test, then implement). Files use CRLF; use the Edit tool or Python with `newline=""` handling like existing code.
- Commits: conventional prefixes, **no Co-authored-by line**. One commit per task. Do not push.
- Never parse `netsh`/`reg` text output; use exit codes only. Program text is English.
- Report text must stay free of user names, paths with user names, full IP/MAC (the existing `Check::new` scrubbing applies to details).
- Provider DoT hosts (port 853): cloudflare `one.one.one.one`, google `dns.google`, quad9 `dns.quad9.net`. Global entries live in `HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\Parameters\DohWellKnownServers\<ip>`.

## Task 1: Safety net

**Interfaces — Produces:**

- `Env` gains `fn restore_point(&self) -> Result<String, String>` (detail text) and `fn export_registry(&self) -> Result<Vec<String>, String>` (file names written).
- Runner: a Phase 0 between environment checks and reading checks, only when `can_write` so far: check `safety.registry_export` (Pass with the file count, or Fail with the reason → `can_write` becomes false and cycles are skipped with that reason) and `safety.restore_point` (Pass, or **Info** with the reason; never blocks). Put these checks in a new `Report.safety: Vec<Check>` field (render a "Safety net" section after Environment; JSON key `safety`). Also render one line there: "To go back: use System Restore, or double-click the .reg files in the reg-backups folder (the folder name is shown on screen)".
- `SystemEnv`: `export_registry` runs `reg.exe` with `export_args` into `%ProgramData%\NetShutUp\reg-backups\<timestamp>\` (create it; all keys must succeed except a key that does not exist, which is skipped by checking existence with `registry::key_exists` first); `restore_point` calls `SRSetRestorePointW` with `BEGIN_SYSTEM_CHANGE` (100) / `MODIFY_SETTINGS` (12), description "NetShutUp self-test", and maps `ERROR_SERVICE_DISABLED` (1058) / non-success status to a readable reason ("System Protection is off or a restore point was made in the last 24 hours" when the status is nonzero). It calls the end record (`END_SYSTEM_CHANGE` 101) at the end of the run only if the begin succeeded: add `Env::finish_restore_point(&self)` called by the runner last.

## Task 2: DoT backend, sidecar and restore (no chain yet)

**Files:** Create `modern/src/dns/dot.rs`; modify `dns/mod.rs` (`pub mod dot;`), `settings/provider.rs` (add `dot_host: &'static str` to `Provider`), `settings/registry.rs`.

**Interfaces — Produces:**
- `registry::values(hive: HKEY, key: &str) -> RegResult<Vec<(String, String)>>`: every value of a key as `(name, "<type>:<data>")` (type as `REG_SZ`/`REG_DWORD`/`REG_QWORD`/`REG_BINARY`/`REG_MULTI_SZ`/`REG_EXPAND_SZ`/`OTHER`; data as text, hex for binary), sorted by name; missing key → `Ok(vec![])`.
- `dot::EntryValues = Vec<(String, String)>`; `trait DotBackend { fn read(&self, address: &str) -> Result<Option<EntryValues>, String>; /* None = no entry */ fn add(&self, address: &str, host: &str) -> Result<(), String>; fn restore(&self, address: &str, saved: &Option<EntryValues>) -> Result<(), String>; }`.
- `#[derive(Serialize, Deserialize, PartialEq, Debug, Clone)] struct Saved { entries: Vec<SavedEntry> }` with `SavedEntry { address: String, values: Option<EntryValues> }`; `dot::sidecar_path(backup: &Path) -> PathBuf` (`<stem>.dot.json`, i.e. `20261117-120000.json` → `20261117-120000.dot.json`; also correct for `...-2.json` and `.reverted.json` stems); `dot::save(path, &Saved) -> Result<(), String>` (write then read back and compare); `dot::load(path) -> Result<Saved, String>`.
- `dot::snapshot(backend, addresses: &[String]) -> Result<Saved, String>`; `dot::add_provider(backend, provider: &Provider) -> Result<(), String>` (every server of the provider, host `provider.dot_host` + `:853`); `dot::restore_all(backend, &Saved) -> Vec<String>` (error messages, keeps going; after each restore reads back and compares with the saved values, mismatch is an error `"<masked address>: entry differs after restoring"`).
- `dot::netsh_add_args(address, host) -> Vec<String>` = `["dns","add","encryption",format!("server={address}"),format!("dothost={host}:853"),"autoupgrade=yes","udpfallback=no"]`; `netsh_delete_args(address)` = `["dns","delete","encryption","server=<address>"]`; `netsh_add_doh_args(address, template)` = `["dns","add","encryption","server=<address>","dohtemplate=<template>"]`.
- `dot::SystemDotBackend` (real): `read` via `registry::values(HKLM, ...DohWellKnownServers\<ip>)` (empty vec and missing key both mean None only when the key does not exist: use `registry::key_exists`); `add`/`restore` run `netsh` with the args above and judge by exit code; `restore` = delete, then re-add with `dohtemplate` from a saved `Template` value (`REG_SZ:<url>`) if present, none if the saved entry was absent. Add a `#[ignore]` test that only reads (`read("1.1.1.1")`) and prints.

## Task 3: Chain over (provider, method) pairs

**Files:** Modify `modern/src/dns/mod.rs`, `settings/plan.rs` (only if signatures need it), `commands.rs` and `selftest/runner.rs` (call sites).

**Interfaces — Produces/changes:**
- `Outcome::Encrypted { provider: String, method: Method, skipped: Vec<String> }` with `#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum Method { Doh, Dot }`; `skipped` entries are `"Cloudflare (DoH)"`-style labels. `FellBack { tried, internet_ok }` keeps shape (`tried` entries are labels). `message()` for DoT: `Encrypted DNS is on: <Name> (DoT, experimental).`; for a skip it reads `Cloudflare (DoH) did not work on this network; using Cloudflare (DoT) instead.` (join several with `, `).
- `dns::run(..., dot: Option<(&dyn dot::DotBackend, &std::path::Path /*apply backup path*/)>, say)`. With `None` the behaviour is exactly today's (DoH only; existing tests keep passing after adding `None`).
- With `Some((backend, backup_path))`, for each provider after its DoH trial fails: first time only → `dot::snapshot` of every server address of every provider in the spec and `dot::save(sidecar_path(backup_path), ..)`; then `dot::add_provider`, write the adapters' DNS as the provider's servers **without DoH** (`State::Value(Value::Dns(..))` with `doh: None`) and read back (as in `write_all`), flush, trial. Success → `Encrypted { method: Dot }` (in `Fastest` mode DoT is only tried for providers whose DoH failed and counts as a candidate with its measured time). Failure → `dot::restore_all` for that provider's addresses from the snapshot, then continue. At the end (`FellBack`) or on any error: restore all DoT entries from the snapshot as well as the adapters' DNS; a restore error becomes `ProgramError` text including the messages.
- Update the two real call sites: `commands::run_dns` passes `Some((&SystemDotBackend, &backup_file))` (the backup path from `apply::apply`'s `Ok(Some(path))`; thread it through `write_profile`), the self-test cycle passes the same with its `backup_path`.

## Task 4: Revert integration and selftest reporting

**Files:** Modify `commands.rs` (`restore_backup`), `selftest/runner.rs`, `selftest/system_env.rs`.

**Produces:**
- `dns::dot::restore_sidecar(backend: &dyn DotBackend, backup_path: &Path) -> Result<Vec<String>, String>`: if `sidecar_path(backup_path)` exists, load it, `restore_all`, and on no errors rename the sidecar to `<stem>.dot.reverted.json`; errors returned for the caller to print; no sidecar → `Ok(vec![])`.
- `commands::restore_backup` calls it (real backend) after the engine revert succeeded and prints any errors like other revert errors (and does not mark the backup reverted if DoT restore failed).
- Runner: after `apply::revert` in a cycle, calls `Env::restore_dot(&self, backup_path: &Path) -> Result<Vec<String>, String>` (real: `restore_sidecar` with `SystemDotBackend`); errors make the `revert` check fail. `Env::dot_entries(&self) -> Vec<String>` (real: `read` for every provider server, lines `"<address>:<N values>"` sorted, addresses are provider addresses so they stay readable; fake: queue like `doh_entries`) compared start vs end in closing as `closing.dot_entries` ("Windows' DoT/DoH server list is as it was"), included in `all_restored`.
- Cycle checks for DoT: when the outcome used DoT or fell back after trying DoT, add `dns.dot` check: Pass `"DoT (experimental) works with <Provider>"` / Info `"DoT was tried and did not work: <reasons>"`; program errors from the DoT path are `dns.trial` Fail with the full reason (already scrubbed by `Check::new`).
